# apt-12 紧急联系人嵌套对象 + 嵌套递归脱敏修复 上线说明

- 模块：`com.evops.apartment.mask`（`SensitiveFields` 递归脱敏 + 日志出口 `maskValue`/`toMaskedJson`）、
  `entity/EmergencyContact` + `entity/EmergencyContactJsonTypeHandler`（新增）、
  `entity/Lease`（新增 `emergencyContact` 嵌套对象，`autoResultMap`）、
  `dto/LeaseCreateRequest`、`service/LeaseService`、`service/LeaseExportService`（导出加列）、
  `task/engine/SignArchiveStepHandler`、`esign/MockESignPlatformClient`、
  `pinyin/PinyinIndexer`（三处日志改同规则脱敏）、`schema.sql`（增量：t_lease.emergency_contact + 版本号 apt-12）。
- 上线日期：2026-09-25
- 缺陷确认与回归证据：见 `docs/apt-12/验证记录.md` 与 `docs/apt-12/evidence/`。

## 1. 背景与缺陷确认

安全抽查发现：**导出的租约文件里证件号（扁平字段）已按规则打码，同表
`emergency_contact` 嵌套对象里的紧急联系人电话却是明文**——规则（name/phone/id-card）
明明配了全表。复核结论：**属实**，根因两条：

1. 脱敏框架只处理实体上的**扁平 String 字段**：`SensitiveFields.readAsString`
   对未打注解的字段一律 `value.toString()` 原样返回，嵌套对象内部的
   `@Sensitive` 成员根本不会被遍历到——导出单元格把整棵对象图原样带出。
2. 日志出口未走规则：`SignArchiveStepHandler`（签署链接送达）、
   `MockESignPlatformClient`（发起签署）、`PinyinIndexer`（截断告警）共 5 处
   把租客/签署人姓名明文写入日志（文件与 `t_ops_log_entry` 采集同染）。

本期修复框架（嵌套对象递归脱敏 + 日志同规则），并按线上结构补齐
`t_lease.emergency_contact` 嵌套对象列作为缺陷载体回归。

## 2. 紧急联系人嵌套对象

- `t_lease` 新增 `emergency_contact VARCHAR(512)`（旧文件库启动幂等补列）：
  JSON 明文存储 `{"name":"...","phone":"...","relation":"..."}`，
  与 apt-2 口径一致——**脱敏只发生在出口，库内保持明文**。
- 实体侧为嵌套对象 `Lease.emergencyContact`（`EmergencyContact` bean）：
  `name`/`phone` 打 `@Sensitive`（与扁平字段同一套注解、同一个规则注册表），
  `relation` 非敏感原样输出。
- 存储走 `EmergencyContactJsonTypeHandler`：专用 ObjectMapper 关闭
  `USE_ANNOTATIONS`，避免 `@Sensitive` 自带的 Jackson 序列化器把值打码后落库。
- 建档接口 `POST /api/apartment/leases` 请求体新增选填 `emergencyContact` 对象；
  签约归档后台任务（apt-5）不涉及该字段，行为不变。

## 3. 嵌套对象递归脱敏（框架修复）

`SensitiveFields` 重构：

- `readAsString(bean, field)`：字段带 `@Sensitive` → 按类型规则脱敏（不变）；
  标量（字符串/数字/布尔/枚举/日期时间）→ 原样转字符串（不变）；
  **嵌套 bean / Map / 集合 / 数组 → 深度遍历对象图，凡 `@Sensitive` 字段一律按
  `SensitiveRuleRegistry` 同规则脱敏，渲染为 JSON（字段声明序）**。
- 新增 `toMaskedJson(Object)`：整对象图递归脱敏渲染，供日志出口打印 bean 使用；
  口径与接口对齐——`@Sensitive` 脱敏、`@JsonIgnore` 不输出；循环引用截断为 null 防死循环。
- 新增 `maskValue(SensitiveType, String)`：单个敏感值按类型同规则脱敏（null 安全），
  供日志语句打印姓名/手机号/证件号使用。
- 规则来源不变：仍是 `SensitiveRuleRegistry`（`application.yml` 默认底 +
  `config/sensitive-rules.yml` 热加载覆盖层），嵌套层级与扁平字段同一份规则，
  热加载对嵌套字段同样即时生效。

各出口口径（修复后）：

| 出口 | 行为 |
|---|---|
| 接口 JSON | Jackson 递归序列化，嵌套成员按 `@Sensitive` 脱敏（原有行为，本期补测试锁定） |
| 租约导出 CSV | 新增「紧急联系人」列（末列），单元格为**脱敏后** JSON；扁平字段口径不变 |
| 日志（文件 + 运维日志库） | 5 处明文点改经 `maskValue` 同规则脱敏；bean 打印一律 `toMaskedJson` |

## 4. 日志出口同规则

以下日志点不再输出明文（规则与接口/导出同源）：

- `SignArchiveStepHandler` 步骤 10「签署链接已送达租客」：租客姓名 → `maskValue(NAME, …)`；
- `MockESignPlatformClient.startTenantSign`：签署人姓名 → `maskValue(NAME, …)`；
- `PinyinIndexer` 三处截断/超限告警：姓名 → `maskValue(NAME, …)`。

约定（本期起）：日志语句打印敏感数据一律经 `SensitiveFields.maskValue`（单值）或
`SensitiveFields.toMaskedJson`（对象），不直接拼明文。

## 5. 回滚

- 框架修复为纯代码变更：回退 `SensitiveFields` 与 5 处日志点即恢复旧行为
  （旧行为即缺陷行为，回滚需安全会签）。
- `emergency_contact` 列为增量可空列，回滚代码后列可保留不删（`ALTER … IF EXISTS` 幂等，
  重跑脚本不受影响）；接口请求体不带 `emergencyContact` 时行为与上一版完全一致。
