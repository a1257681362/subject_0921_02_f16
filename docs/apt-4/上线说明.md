# apt-4 交接班线上化 + DFA 敏感词过滤 上线说明

- 模块：`com.evops.apartment.sensitive`（新增）、`com.evops.apartment`（交接班 + 既有写入接入）
- 上线日期：2026-09-23

## 1. 本次交付内容

1. **交接班记录线上化**：替代纸质交接本。交班登记（DRAFT 待确认）→ 接班人确认（CONFIRMED），
   支持按小区/楼栋/班次/日期区间/状态检索；只增不删、不可重复确认、禁止自交自接。
2. **DFA 敏感词过滤**：词典存库（`t_sensitive_word`）后台维护，新增/修改/启停后引擎整体重建、即时生效。
   - **归一化（变形词）**：逐字符 NFKC（全角→半角）、大小写折叠、零宽字符剥离、
     形近替换（`0→o 1→i 3→e 4→a 5→s 7→t @→a $→s`）；
   - **分隔符插空也命中**：归一化时丢弃所有非字母数字字符，「代-开发票」「代 开·发*票」均命中「代开发票」；
   - **位置可定位**：命中结果回映原文字位 `[start,end)`，区间覆盖首尾之间的插空字符；
   - **分级处理**：`actionLevel=1` 打码（区间替换为 `*` 后放行），`=2` 拦截（业务写入失败、整体回滚）。
3. **操作痕迹（出状况能定位到人）**：
   - `t_sensitive_audit`：每一次命中逐词逐字段留痕——账号、请求号、模块、业务定位、字段路径、
     词条、字位、原文片段、打码结果、时间。**拦截痕迹以 REQUIRES_NEW 独立事务落库，业务回滚不影响留痕**；
   - `t_sensitive_word_op_log`：词典每一次新增/修改/启停留痕（变更前后快照、操作人、时间），只增不改。
4. **接入范围**：交接班（小区/楼栋/待办/内容）、台账登记（地址三字段/备注）、台账冲销（原因）、
   租约建档（新增 `remark` 列）、退租（验房备注、每条扣除项名称/备注）。
   租客姓名/手机/证件号等结构化字段不扫描，避免误伤。
5. **数据范围沿用 apt-3**：交接班检索/详情按 SELF（本人交班或接班）/SCOPE（授权小区）/ALL 放行，
   每次放行落 `t_data_scope_audit`；命中痕迹与维护留痕仅 ALL 角色（主管、管理员）可查。

## 2. 新增接口

交接班（管家/片区管家/主管/管理员均可，按数据范围过滤）：

| 方法 | 路径 | 权限码 |
|---|---|---|
| POST | `/api/apartment/handovers` | `apartment:handover:create` |
| POST | `/api/apartment/handovers/{id}/confirm` | `apartment:handover:confirm` |
| GET | `/api/apartment/handovers` | `apartment:handover:view` |
| GET | `/api/apartment/handovers/{id}` | `apartment:handover:view` |

敏感词后台：

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| GET | `/api/apartment/sensitive/words` | `apartment:sensitive:manage` | 词典查询（status/category/keyword） |
| POST | `/api/apartment/sensitive/words` | `apartment:sensitive:manage` | 新增（重复归一形态拒绝） |
| POST | `/api/apartment/sensitive/words/{id}` | `apartment:sensitive:manage` | 修改 |
| POST | `/api/apartment/sensitive/words/{id}/status` | `apartment:sensitive:manage` | 启停，体 `{"active":false}` |
| GET | `/api/apartment/sensitive/word-logs` | `apartment:sensitive:audit` | 维护留痕 |
| GET | `/api/apartment/sensitive/audits` | `apartment:sensitive:audit` | 命中痕迹（username/module/bizRef/actionTaken） |

权限分配：`sensitive:manage` 仅管理员；`sensitive:audit` 管理员+主管；
交接班 4 个权限点授予管家/片区管家/主管/管理员。

拦截响应约定：HTTP 200 + `{"success":false,"message":"内容含违规词已拦截：字段[xxx]命中[词(位置a-b)]…"}`，
前端按字段与字位高亮提示。

## 3. 初始种子词（8 个，仅首建库播种）

| 词 | 类别 | 级别 |
|---|---|---|
| 代开发票、刷单返利、联系电话、赌博、私刻公章 | AD / ILLEGAL | 2 拦截 |
| 加微信、有房出租、免押金 | AD | 1 打码 |

种子仅在 `t_sensitive_word` 为空时写入，后台维护结果重启不丢、不被重置。
归一化后同形的两个词条不能共存（新增时被拒绝，提示维护原词条）。

## 4. 配置

```yaml
evops:
  sensitive-word:
    enabled: true        # 应急总开关：false 时所有写入跳过扫描（仅限紧急窗口）
    mask-char: "*"       # 打码字符
```

## 5. 部署步骤

1. 备份 `data/evops.mv.db` 与在用 jar。
2. `mvn -DskipTests package`，替换 jar 后启动。
3. schema 全部为 `CREATE TABLE IF NOT EXISTS` / 幂等 `ALTER TABLE ADD COLUMN IF NOT EXISTS`，
   旧库自动升级：新增 4 张表、`t_lease` 增加 `remark` 列、权限点 14–19 与授权、种子词、版本登记。
4. 验证：按 `docs/apt-4/验证记录.md` 冒烟。

## 6. 回滚

停用开关即可临时旁路过滤（`evops.sensitive-word.enabled=false` 重启）；
交接班功能与权限点为纯增量，回滚 jar 不影响既有数据。新增列/表保留无副作用。
