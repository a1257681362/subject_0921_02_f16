# apt-3 多角色权限并集 上线说明

- 模块：`com.evops.rbac`（新增）、`com.evops.apartment`（接入鉴权与数据范围）
- 对应规划项：一个账号兼多个角色，权限按并集计算
- 上线日期：2026-09-22

## 1. 本次交付内容

1. **多角色并集**：一个账号可挂多个角色；菜单、按钮权限取全部启用角色的并集。
2. **数据范围按最宽角色放行**：范围等级 `SELF（仅本人经办） < SCOPE（指定片区） < ALL（全部）`，
   多角色取最宽等级放行；SCOPE 为多个片区授权时取小区并集。
3. **放行留审计**：每一次按数据范围放行的查询/写入均落 `t_data_scope_audit`
   （账号、当次生效角色、最宽范围、授权来源角色、小区、资源、查询条件摘要、返回行数、时间）。
4. **停用即时收权**：授权每请求实时查库组装、不缓存。
   - 角色停用：该角色权限与数据范围从下一次请求起立即从并集中移除，令牌不变；
   - 账号停用：下一次请求即 401，同时吊销其全部令牌，重新启用后必须重新登录。
5. **登录认证**：`POST /api/auth/login` 换不透明令牌（`X-Auth-Token` 头，默认有效期 12 小时），
   `GET /api/auth/me` 返回菜单/按钮并集与最宽数据范围，`POST /api/auth/logout` 吊销令牌。

## 2. 新增接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login` | 匿名 | 账号口令登录，返回令牌与身份快照 |
| POST | `/api/auth/logout` | 持令牌 | 吊销当前令牌 |
| GET  | `/api/auth/me` | 持令牌 | 当前角色、菜单/按钮并集、最宽数据范围 |
| POST | `/api/rbac/users/{username}/status` | `rbac:admin:manage` | 账号启停，体 `{"active":false}` |
| POST | `/api/rbac/roles/{roleCode}/status` | `rbac:admin:manage` | 角色启停，体 `{"active":false}` |

公寓原有接口路径不变，全部改为需登录并按表挂权限码：

| 接口 | 权限码 |
|---|---|
| 台账登记 / 冲销 / 流水 | `apartment:property:register` / `apartment:property:reverse` / `apartment:property:view` |
| 租约建档 / 检索 / 导出 | `apartment:lease:create` / `apartment:lease:view` / `apartment:lease:export` |
| 办理退租 / 退租详情 | `apartment:checkout:handle` / `apartment:checkout:view` |

HTTP 约定：未登录/令牌失效/账号停用 → **401**；已登录但缺权限或越数据范围 → **403**。

## 3. 内置账号（仅首版，首登后必须改密）

| 账号 | 初始口令 | 角色 | 数据范围 |
|---|---|---|---|
| steward01 | steward123 | 管家 | SELF |
| supervisor01 | supervisor123 | 主管 | ALL |
| area01 | area123 | 片区管家 | SCOPE：示例小区 |
| combo01 | combo123 | 管家 + 主管 | 并集：按钮取并集、范围 ALL（主管放行） |
| admin | admin123 | 系统管理员 | ALL，含账号角色启停管理 |

口令以 SHA-256 十六进制存于 `t_rbac_user.password_hash`。新增账号/改密暂通过运维侧更新该列
（`SELECT RAWTOHEX(HASH('SHA-256', STRINGTOUTF8('新口令')))` 可在 H2 中生成，或用 Java 端 `Passwords.sha256`）。

## 4. 部署步骤

1. 备份：停服前复制 `data/evops.mv.db`（H2 文件库）与当前在用 jar。
2. 打包：`mvn -DskipTests package`，产物 `target/evops-base-0.1.0-SNAPSHOT.jar`。
3. 发布：替换 jar 后启动；`schema.sql` 启动自动执行，apt-3 全部为
   `CREATE TABLE IF NOT EXISTS` / 幂等 `MERGE` 种子 / 版本登记，对旧库无破坏、可重复执行。
4. 验证：按 `docs/apt-3/验证记录.md` 执行冒烟（登录、并集、越权 403、停用收权、审计落库）。
5. 通知前端：公寓接口请求一律带 `X-Auth-Token`；菜单/按钮以 `/api/auth/me` 的
   `menus`、`buttons` 并集渲染；未获 401 时跳登录。

## 5. 回滚步骤（按影响面从小到大）

### 5.1 一级回滚：开关降级（无需重启部署，约 1 分钟）

将配置（外部化配置文件或启动参数 `-Devops.rbac.enabled=false`）设置：

```yaml
evops:
  rbac:
    enabled: false
```

- 当前版本配置未接热加载，需重启进程生效；重启后令牌过滤器与权限拦截器全部旁路，
  `/api/**` 恢复 apt-2 的匿名可达行为，公寓业务可立即继续（**此时无接口级鉴权，仅限紧急窗口使用**）。
- RBAC 表与数据保留不动；脱敏（apt-2）不受影响。

### 5.2 二级回滚：代码包回退

1. 停服，用上线前备份的旧 jar 替换现网 jar。
2. 旧版本不识别新增表，启动与运行均不受影响（新表只是闲置）。
3. 启动后公寓接口恢复旧行为；恢复完成后记录回滚时间与原因。

### 5.3 三级回滚：清理 apt-3 数据（仅在确认废弃本特性时执行）

必须在**停服且已备份 H2 文件**后，通过 H2 命令行对备份副本执行：

```sql
DROP TABLE IF EXISTS t_data_scope_audit;
DROP TABLE IF EXISTS t_rbac_login_token;
DROP TABLE IF EXISTS t_rbac_role_permission;
DROP TABLE IF EXISTS t_rbac_user_role;
DROP TABLE IF EXISTS t_rbac_data_scope;
DROP TABLE IF EXISTS t_rbac_permission;
DROP TABLE IF EXISTS t_rbac_role;
DROP TABLE IF EXISTS t_rbac_user;
DELETE FROM t_evops_schema_version WHERE version_no = 'apt-3';
```

业务表（台账、租约、退租、扣除）在 apt-3 中**未做任何结构变更**，无需处理。

### 回滚后验证

- 一级回滚：不带令牌访问 `GET /api/apartment/leases` 应 200；确认业务主流程可走通后尽快修复并重新打开开关。
- 二级回滚：`/api/health` 200，公寓建档/检索/退租主流程通；旧库文件可正常打开。

## 6. 注意事项

- `application.yml` 中 `shiro.annotations.enabled=false` 维持不变（注解代理与事务代理冲突的旧约束仍在）。
- 数据范围中 SCOPE 按**台账登记的小区名**归集到房源编号；新小区必须先由主管/管理员完成台账登记，
  片区管家才能看到该片区租约。
- 令牌有效期由 `evops.rbac.token-ttl-hours` 调整（默认 12 小时）。
- 放行审计为 fail-closed：审计写失败则该请求失败，不允许出现无痕放行；
  审计表增长后由运维按保留期定期归档。
