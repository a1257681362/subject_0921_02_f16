# apt-8 签约结果正式 Word 报告（poi-tl） 上线说明

- 模块：`com.evops.apartment.report`（新增：dto/entity/mapper/service/web + `ReportProperties`/`ReportConfig`）、
  `resources/templates/sign-result.docx`（poi-tl 模板）、`schema.sql`（增量：1 张版本表 + 权限点 33–35
  + `report_demo` 角色与 `demo01` 账号）、`application.yml`（`evops.sign-report.*`）、`pom.xml`（poi-tl 1.12.2）
- 上线日期：2026-09-24

## 1. 背景与口径

上面要求签约结果出正式 Word 版报告。房源台账历史包袱不轻，本期**只从新数据理起**：
报告口径基于新台账（`t_property_ledger` 的 REGISTER 流水）按公寓楼归集房源，
关联新签租约（`t_lease`），不回溯、不改动历史台账与历史租约。

报告由 **poi-tl 模板引擎**渲染为正式 `.docx`：

- **页眉带公寓楼名称**：页眉放 `{{buildingName}}`，poi-tl 默认渲染页眉标签；
- **租约明细做成循环表格行**：数据行用 `LoopRowTableRenderPolicy`（onSameLine 模式），
  一条租约复制一行；行内字段用方括号语法 `[contractNo]`、`[monthlyRent]` 等；
- **租金合计自动汇总**：`{{totalRent}}` 由本期明细的 `monthly_rent` 服务端 `BigDecimal` 求和，
  不依赖 Word 域公式；**明细为空时合计为 0.00，不抛异常**（reduce 给零初值，空列表只移除模板行）。

> 模板结构约定（poi-tl）：循环触发行第一个单元格写 `{{leases}}[seq]`（触发标签渲染为空、
> `[seq]` 留序号），其余单元格写 `[字段名]`。模板由 POI API 规范生成（保证行内子标签
> 归属 LoopRow 解析器、不被顶层解析提前清空）。模板若需调整，可用测试树里的
> `com.evops.apartment.report.SignTemplateTool`（main 方法）重新生成，再随包发布。

## 2. 不覆盖与版本登记

- 文件只以 **`CREATE_NEW`** 落归档目录 `evops.sign-report.archive-dir`，
  按 `归档根/小区/楼栋/` 分目录，文件名 `签约结果报告_楼栋_v版本号_yyyyMMddHHmmss.docx`；
- 同一公寓楼每出一版 **`version_no` +1**（取该楼最大版本号 +1，首版为 1），
  在 `t_sign_report_version` 登记一行（楼栋、小区、版本号、文件名/路径、明细条数、租金合计、
  筛选区间、请求号、操作人、业务时间、数据版本）；
- **历史报告不被覆盖**：文件 `CREATE_NEW` + 表上 `uk(building_name, version_no)`、
  `uk(file_path)` 三重兜底；并发同楼栋撞版本号/文件名时自动重算重试（最多 5 次），
  撞库的候选孤儿文件会被清理，不留垃圾。

## 3. 新增接口（`/api/apartment/sign-reports/**`，均需登录）

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| POST | `/generate` | `apartment:sign-report:generate` | 按公寓楼（+可选小区/起租日期区间）生成报告，落归档目录并登记版本 |
| GET | `` | `apartment:sign-report:view` | 版本记录列表（buildingName 可选，按数据范围过滤） |
| GET | `/{id}` | `apartment:sign-report:view` | 版本详情（按数据范围放行） |
| GET | `/{id}/download` | `apartment:sign-report:view` | 下载该版归档 docx（历史文件不可变，重复下载同字节） |

生成请求体：`buildingName`（必填）、`community`（可选，多小区同名楼时必传）、
`startFrom`/`startTo`（可选，按租约起租日过滤，`yyyy-MM-dd`）、`requestNo`、`operator`（登录后以账号为准）。

数据范围沿用 apt-3，逐动作落数据放行审计：

- **SELF**：可出报告（与租约建档口径一致），租约明细仅本人经办、列表/下载仅本人生成的版本；
- **SCOPE**：只能对授权小区内的楼栋出报告（`requireCommunityInScope`），
  租约明细经 `applyLeaseScope` 限授权片区房源，版本列表/下载仅授权小区；台账查不到该楼时要求显式传小区，避免越区出空报告；
- **ALL**：不限。

## 4. 新增表与权限

- `t_sign_report_version`：报告版本登记（只增不改），唯一键
  `uk_sign_report_building_ver(building_name, version_no)` 与 `uk_sign_report_file(file_path)`；
  索引 `(building_name,id)`、`(operator)`。
- 权限点（接着 apt-7 的 32 号）：
  - `33 apartment:menu:sign-report`（菜单）
  - `34 apartment:sign-report:generate`（生成）
  - `35 apartment:sign-report:view`（查看/下载）
- **演示账号（本次范围内最小授权）**：
  - 新角色 `report_demo`（id=5，`签约报告演示`），**只授 33–35**，
    不挂台账/租约/退租/交接班/签约任务/敏感词/额度/运维日志等任何既有功能；
    每次启动幂等 `DELETE` 该角色 33–35 之外的授权，防止被“全量授权”种子带权；
  - 数据范围 `SCOPE = 示例小区`（id=5）；
  - 新账号 `demo01`（id=6，显示名“签约报告演示账号”）/ 初始口令 **`demo123`**，只挂 `report_demo`。
- 主管、管理员在既有公寓权限外可出报告（显式授 33–35，管理员不依赖 apt-3 段 CROSS JOIN，口径不漂移）；
  管家/片区管家本期不授（如需出报告另行授权）。

全部为 `CREATE TABLE IF NOT EXISTS` / `MERGE` / 幂等 `DELETE`，旧文件库启动自动升级，无手工 DDL。

## 5. 配置

```yaml
evops:
  sign-report:
    archive-dir: archive/sign-reports   # 归档根目录（可改绝对路径）；按 小区/楼栋 分目录，只新建不覆盖
    template-classpath: templates/sign-result.docx
```

归档根目录已加入 `.gitignore`（`archive/`），不随版本库提交。

## 6. 部署步骤

1. 备份 `data/evops.mv.db` 与在用 jar。
2. `mvn -DskipTests package`，替换 jar 后启动；schema 自动增量升级（建版本表、补 33–35 权限、
   建 `report_demo` 角色/数据范围与 `demo01` 账号）。
3. `demo01 / demo123` 登录确认 `/api/auth/me`：menus 仅 `apartment:menu:sign-report`，
   buttons 仅 generate/view，dataScope 为 SCOPE 含“示例小区”；访问台账/租约等接口应 403。
4. 冒烟：对“示例小区”内已签约的楼栋 `POST /generate` → 返回版本号/明细条数/租金合计；
   `GET /{id}/download` 打开 docx：页眉有公寓楼名、明细逐租约成行、合计=明细之和；
   再生成一版确认版本号 +1、旧文件仍在。
5. 空明细：对有台账无租约的楼栋生成，确认成功且合计行显示 0.00、无数据行。
6. 逐条结论见 `docs/apt-8/验证记录.md`。建议演示后改 `demo123` 或停用 demo01。

## 7. 回滚

- 纯增量：回滚 jar 后版本表、归档文件保留，无其他模块读写，不影响 apt-1～apt-7。
- 收演示账号：停用 `demo01`（账号停用即时收权、令牌当次失效）或停用/解绑 `report_demo`；
  不影响主管/管理员（其报告权限为附加，停用该角色不收回其既有角色权限）。
- 归档文件只落本地目录；如改对象存储，替换 `SignReportService` 落盘一段即可，版本登记口径不变。
