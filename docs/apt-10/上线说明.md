# apt-10 房源归属树闭包表 上线说明

- 模块：`com.evops.apartment.tree`（新增 `entity/{PropertyNode,PropertyClosure}`、
  `mapper/{PropertyNodeMapper,PropertyClosureMapper}`、`dto/{NodeCreateRequest,NodeMoveRequest,
  NodeSortRequest,NodeView}`、`service/PropertyTreeService`、`web/PropertyTreeController`）、
  `service/Audits`（包级工具类改为 public 供跨包复用）、
  `schema.sql`（增量：`t_property_node`、`t_property_closure`、权限点 36-38 与角色授权）。
- 上线日期：2026-09-24

## 1. 背景与口径

区域总提的新功能。管家自己记了本流水账，对账全靠房源归属树：小区 → 楼栋 → 层 → 房间的归属关系
原来只隐含在台账文本里，子树有哪些房、某房归属哪条链、同级怎么排，都要现场拼。本期把归属树改成
**闭包表（Closure Table）模型**，把树形查询变成表上的等值/联表查询，不做递归：

- `t_property_node`：节点表。`parent_id` 记**直接父**（根为 NULL），`sort_order` 记同级次序，
  `community` 冗余到每个节点（供 apt-3 数据范围 SCOPE 按小区过滤；换父时整子树一起更新）。
- `t_property_closure`：闭包表。每个节点与其**每一**祖先之间一行，`distance` 为代际距离
  （0=自身、1=直接父子、越大越远），主键 `(ancestor_id, descendant_id)` 天然防重复路径。

三类操作全部走表结构：

| 需求 | 实现 |
|---|---|
| 子树查询 | `WHERE ancestor_id = 根` JOIN 节点表，按 `distance, parent_id, sort_order` 排 |
| 祖先链 | `WHERE descendant_id = 节点` ORDER BY `distance DESC`，恒为「根 → … → 自己」 |
| 同级排序 | 节点表 `sort_order` 列；`/nodes?parentId=` 按其升序，排序接口只改该列 |

## 2. 拖拽换父：子孙自动跟随

同一数据库事务内四步（全部成功才提交，任一失败整树回滚）：

1. `UPDATE t_property_node SET parent_id, sort_order` 改直接父；
2. 删旧路径：删除「被拖子树成员 ↔ 原子树上层」之间的闭包边，**子树内部边保留**
   （`ancestor` 落在子树内的行不删）；
3. 接新路径：新父的每个祖先（含新父自身）× 被拖节点的每个后代（含自身）笛卡尔接边，
   `distance = 祖先到新父 + 1 + 节点到后代`，子孙边随之自动重建；
4. 整子树（含自身）`community` 更新为新父小区——归属迁移后对账/SCOPE 过滤口径不残留旧小区。

`newParentId` 传空表示**挪为根**：只做第 2 步删光旧祖先路径，保留子树内部边。

## 3. 环状引用直接拒绝

换父前先做环检测：`SELECT COUNT(*) FROM t_property_closure WHERE ancestor_id=被拖节点 AND descendant_id=新父`，
命中（新父是被拖节点**自身**或其**后代**）即抛业务错误「不能挂到自身或自己的子孙节点下（环状引用）」，
事务回滚、不改一行闭包边。挂到子孙下被拒绝是验收必查项（见验证记录第 3 节）。

## 4. 维护日志按合同号可查（验收必查）

建节点 / 换父 / 排序请求体支持可选 `contractNo`：服务层在打 INFO 日志期间把该合同号绑到 apt-6 的
日志 MDC，落库的 `t_ops_log_entry.contract_no` 即带该合同号。管家在「公寓楼-运维日志」菜单
`GET /api/apartment/ops-log/entries?contractNo=合同号` 即可一次拉出该合同相关的全部归属变更
（新增/换父成功/排序；环拒绝另有 WARN 行）。日志检索仍走 apt-6 口径：必带合同号或 TraceId、
14 天窗、≤200 条、SELF/SCOPE 数据范围校验。未带 `contractNo` 的维护动作日志照常落库（contractNo=N/A），
不影响主流程。

## 5. 权限与数据范围

- 新增权限点 36 `apartment:menu:property-tree`（菜单）、37 `apartment:property-tree:manage`（维护）、
  38 `apartment:property-tree:view`（查询），授管家/片区管家/主管/管理员；
  apt-8 的 `report_demo`（demo01）不授——该角色每轮 schema 初始化被幂等收权固定为 33-35。
- 数据范围沿用 apt-3：SELF 仅本人经办节点（建子节点/换父/排序均校验经办人）、
  SCOPE 按节点冗余 `community` 过滤与写校验、ALL 全部；每次查询/维护落 `t_data_scope_audit`。

## 6. 新增表

`t_property_node`：`uk_property_node_code(node_code)`、索引 `(parent_id, sort_order)`、`(community)`，
带 apt-1 审计四字段（request_no/operator/biz_time/data_version）+ updated_at。

`t_property_closure`：主键 `(ancestor_id, descendant_id)`，另建 descendant、ancestor 两个单列索引
（H2 主键只按首列 ancestor 组织，祖先链按 descendant 查需独立索引）。

旧文件库启动自动 `CREATE TABLE IF NOT EXISTS`，无手工 DDL；schema 重跑（mode=always）幂等，
权限 MERGE + report_demo 收权语句多次执行结果不变。

## 7. 接口（均需登录，`/api/apartment/property-tree/**`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/nodes` | 新增节点。parentId 空=建根（community 必填）；非空则继承父小区并校验父归属 |
| POST | `/nodes/move` | 换父 `{nodeId, newParentId, sortOrder, contractNo?}`；newParentId 空=挪为根；成环拒绝 |
| POST | `/nodes/sort` | 同级排序 `{nodeId, sortOrder}`，不动归属 |
| GET | `/nodes?parentId=` | 同级节点（不传返回根列表），sort_order 升序 |
| GET | `/nodes/{rootId}/subtree` | 子树（含根） |
| GET | `/nodes/{nodeId}/ancestors` | 祖先链（含自身，根→自己） |
