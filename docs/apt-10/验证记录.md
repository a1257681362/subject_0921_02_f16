## 区域总验收必查项

### A. 祖先链顺序正确 —— 通过
- 用例 `ancestorChain_returnsRootToSelfInCorrectOrder`：建「示例小区 → 2栋 → 3层 → 301」四级，
  GET `/nodes/301/ancestors` 返回 4 行，id 顺序恰为 小区、2栋、3层、301，
  distance 依次 3、2、1、0（`ORDER BY c.distance DESC`，最后一行是自己）。
- 换父后顺序随之正确（见 C/D），祖先链不靠内存拼装，直接来自闭包表。

### B. 挂到子孙下被拒绝 —— 通过
- 用例 `cycle_moveUnderSelfOrDescendant_rejected_andStructureUnchanged`：
  - 把 1栋 挂到其子孙 2层 下 → HTTP 200 但业务 `success=false`，message 含「环状引用」；
  - 把 1栋 挂到自身下 → 同样拒绝；
  - 拒绝后再查：1栋 祖先链仍为「小区 → 1栋」，2层 仍为「小区 → 1栋 → 2层」，
    闭包边一行未改（环检测先于任何写操作，事务回滚）。
- 环检测口径：`t_property_closure` 中 `(ancestor=被拖节点, descendant=新父)` 有行即拒，
  覆盖「挂自身」（distance=0 自身行命中）与「挂任意后代」。

### C. 日志能按合同号查到 —— 通过（验收时必查）
- 用例 `maintenanceLogs_queryableByContractNo_acceptanceMustCheck`：新增 3 个节点 + 1 次换父
  均带 `contractNo=HT-TREE-LOG-0001`，轮询确认 `t_ops_log_entry` 落库后，以管家身份
  GET `/api/apartment/ops-log/entries?contractNo=HT-TREE-LOG-0001`：
  count ≥ 2，返回行全部 `contractNo` 同值、`username=steward01`，且分别命中
  「房源归属树新增节点」与「房源归属树换父成功」两类业务日志。
- 链路：服务层 `withContract` 把合同号写入 apt-6 MDC → logback `OPS_DB` appender 采集 →
  按合同号检索，沿用 apt-6 的 SELF/SCOPE 范围与 14 天窗口径。

## 其余用例逐条结论

### 1. 子树查询走表结构、取全且只取子集
- 用例 `subtree_returnsWholeSubtreeAndOnlyIt`：根下甲栋(sort 10)、乙栋(sort 20)、甲栋101，
  整树返回顺序 [根, 甲栋, 乙栋, 甲栋101]（先按 distance 分层、同父按 sort_order）；
  甲栋子树恰为 [甲栋, 甲栋101]，不含根与乙栋。

### 2. 同级排序走表结构，排序接口即时生效
- 用例 `siblings_orderedBySortOrder_andSortApiReorders`：30/10/20 三个同父节点初始按
  sort_order 返回 [10,20,30]；POST `/nodes/sort` 把 30 改为 5 后，返回 [30,10,20]，
  排序只改 sort_order/data_version，不动 parent_id、不重建闭包。

### 3. 拖拽换父子孙自动跟随（闭包边 + 小区归属整体迁移）
- 用例 `moveNode_descendantsFollow_closureAndCommunityMigrate`（主管跨「旧小区/其他小区」两棵树）：
  把 1栋（下挂 2层、201）拖到新小区根下后：
  - 2层 祖先链 [新小区, 1栋, 2层]、201 祖先链 [新小区, 1栋, 2层, 201]，旧小区均不在链中；
  - 新根子树含 1栋/2层/201，旧根子树 subtree 只剩旧根自己；
  - 新子树全部节点 community=其他小区（整子树冗余列跟随更新）。
- 用例 `moveNode_toRoot_detachesWholeSubtree`：把 1栋 拖为根（newParentId 空）后，
  101 祖先链为 [1栋, 101]，根列表出现 1栋；旧根边删净、子树内部边保留。

### 4. 鉴权与数据范围
- 用例 `auth_401_403_andScopeCrossCommunity_andDemoLeastPrivilege`：
  未登录访问 401；demo01（report_demo 仅 33-35）查询/维护均 403；
  片区管家（SCOPE=示例小区）建示例小区根成功、建「其他小区」根 403；
  主管在「其他小区」建的根，片区管家根列表不可见（SCOPE 按 community 过滤）。

### 5. schema 重跑幂等、权限稳定
- 用例 `schemaRerun_idempotent_permissionsStable`：测试内手工再执行一遍 `schema.sql`
  （模拟旧文件库二次启动 mode=always）：管家按钮仍含 `apartment:property-tree:view`；
  demo01 仍不含任何归属树权限、且保留 `apartment:sign-report:view`（apt-8 幂等收权未被突破）；
  闭包两表 CREATE IF NOT EXISTS、权限 MERGE 均无冲突。
