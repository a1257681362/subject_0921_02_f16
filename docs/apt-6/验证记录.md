1. `OpsLogQueryService` 条件构造器的 value 参数无论条件是否生效都会求值，

## 2. 真实启动冒烟（独立文件库 + 临时端口 8099）

离线环境无法下载打包插件，以 `target/classes` + surefire 实际使用的本地依赖
（93 个 jar，剔除测试与冲突旧 slf4j 实现）启动，等价生产 classpath。

启动日志：

```
INFO ... logger=c.evops.common.opslog.OpsLogSinkService
     - 运维日志采集已启动：有界队列 2000，库内保留 14 天
INFO ... logger=com.evops.EvopsApplication - Started EvopsApplication in 11.0s
```

冒烟步骤（真实账号）：

1. supervisor01 登录登记台账 `PROP-SMOKE-001`（示例小区），响应头
   `X-Trace-Id: 1a0cde596f41c55aa4af7b6`。
2. `/api/auth/me`：steward01 的 menus 含 `apartment:menu:ops-log`、
   buttons 含 `apartment:opslog:view`；supervisor01 的 menus **不含**该入口。
3. steward01 带 `X-Trace-Id: smoke-trace-ht-0001` 建档 `HT-SMOKE-0001`：
   响应头与响应体 `traceId` 均为入站值。
4. 等采集落库后按合同号检索（管家本人合同，SELF 放行）：

   ```
   GET /api/apartment/ops-log/entries?contractNo=HT-SMOKE-0001
   → count=1 droppedByCollector=0
     INFO smoke-trace-ht-0001 steward01 租约建档成功 contractNo=HT-SMOKE-0001 ...
   ```

5. 同一接口用 supervisor01 令牌 → **403**；不带任何参数 →
   200 + `success=false`「检索必须提供合同号或 TraceId」，响应体仍带本次 traceId。
6. 后台任务续传：带 `X-Trace-Id: smoke-trace-bg-0002` 发起签约归档任务
   `HT-SMOKE-BG-0001`，秒回 `traceId=smoke-trace-bg-0002`；约 10 秒后 SUCCESS 100%。
   按该 TraceId 聚合：**count=13，覆盖三个线程**
   （http-nio 请求线程 + async-task-1 + async-task-2——等租客签署后任务被另一工作线程重领，仍同号），
   其中工作线程行 11 条，含 `任务 ... 执行成功 100%`。
7. 文件日志 `logs/evops-base.log` 实际固定格式：

   ```
   2026-09-23 10:53:45.843 INFO  [evops-base,async-task-1] traceId=smoke-trace-bg-0002
     contractNo=HT-SMOKE-BG-0001 user=steward01 logger=c.e.a.esign.MockESignPlatformClient
     - [mock-esign] ping ok
   ```

8. `GET /api/apartment/ops-log/console` → 200 `text/html;charset=utf-8`，检索台正常渲染；
   数据接口无令牌 401（空壳页本身不鉴权，与电子签章演示台同口径）。

**二次启动幂等收权追加验证**（发现并修复的问题）：apt-3 段的种子 MERGE 每轮启动都执行
（`sql.init.mode=always` 重跑全脚本），其中 admin「CROSS JOIN 全部权限点」、
supervisor「CROSS JOIN apartment 模块」会在**旧库第二次启动**时把新增的 25–26 授出去。
schema 末尾补幂等收权 DELETE 后，对同一份文件库连续启动两次实测：
两轮 `/api/auth/me` 中 admin 的运维日志菜单/按钮均为空（直接调接口 403），管家侧入口正常。

验证后已停止应用并清理临时库与日志目录；工作区未残留运行态进程。
