# apt-6 全链路 TraceId + 运维日志归集 上线说明

- 模块：`com.evops.common.trace`（新增）、`com.evops.common.opslog`（新增）、
  `com.evops.apartment.opslog`（新增）、`logback-spring.xml`（新增）、`schema.sql`（增量）
- 上线日期：2026-09-23

## 1. 本次交付内容

旺季前备系统：老员工休假排障不断档，不再在几十段日志里来回翻。

1. **入口生成 TraceId**：`TraceFilter` 最外层（先于令牌鉴权）挂 `/api/*`，
   入站带 `X-Trace-Id` 且合法（`[A-Za-z0-9-]{8,64}`，挡日志注入）则沿用，否则服务端生成，
   每次请求必有 TraceId，写入 SLF4J MDC；鉴权后令牌过滤器补写账号。
2. **响应回带**：响应头 `X-Trace-Id` + 响应体 `traceId`（`ApiResponse` 固定字段）同值，
   401/403/参数校验失败/兜底异常都带；前端截图、租客投诉凭此号定位。
3. **线程池传递**：`MdcTaskDecorator` 装配到 apt-5 任务工作池（及任何 Spring 线程池），
   请求线程异步日志自动续传；**后台任务执行器另按任务表 `trace_id` 在工作线程重新绑定**
   （调度线程没有请求 MDC），并同时绑定合同号（bizRef）与发起人（operator），
   finally 清空 MDC，池化线程不串号。同一合同「发起请求 → 调度认领 → 20 个步骤」全部同号。
4. **按合同号聚合**：租约建档/退租/签约任务提交入口把合同号绑入 MDC（失败分支也在上下文内），
   关键业务动作打 INFO 日志；管家按合同号一次拉出该请求（含后台任务）的全部日志。
5. **日志格式字段固定**（`logback-spring.xml`，不允许各环境私改字段名/顺序）：

   ```
   时间 级别 [应用,线程] traceId=.. contractNo=.. user=.. logger=.. - 消息
   堆栈
   ```

   无上下文键统一输出 `N/A`。
6. **日志保留 14 天（两条线）**：
   - 文件：`logs/evops-base.log`，按天 + 100MB 切分、gz 归档、`maxHistory=14`、总量上限 2GB；
   - 库内：采集落 `t_ops_log_entry`，每日 01:23 删除 14 天前记录。
   采集口径固定：`com.evops` 的 INFO+，其他框架（Spring/Tomcat/Hikari 等）WARN+。
   采集为**有界队列（2000）+ 单线程批量异步**：满则丢新并计数（接口结果中
   `droppedByCollector` 可见），日志故障绝不阻塞或拖垮业务；Sink 未就绪/关闭期间不落库，
   文件日志始终完整。
7. **操作入口收进公寓楼菜单，权限只放给管家**：权限点
   `apartment:menu:ops-log`（25，菜单）、`apartment:opslog:view`（26，检索）
   **仅授管家与片区管家**；主管/管理员/兼主管账号中主管侧不带此权限（combo 因兼管家仍有，符合并集口径）。
   检索台 `GET /api/apartment/ops-log/console`（自包含 HTML，粘贴令牌），
   数据接口强制鉴权：未登录 401、非管家 403。

## 2. 新增接口（`/api/**`）

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| GET | `/api/apartment/ops-log/entries` | `apartment:opslog:view` | 按合同号/TraceId 聚合检索（必带其一） |
| GET | `/api/apartment/ops-log/console` | （空壳页不鉴权） | 自包含检索台 HTML，数据走鉴权接口 |

`/entries` 参数：`contractNo` / `traceId`（至少其一）、`level`(INFO/WARN/ERROR)、
`from` / `to`（`yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss`）、`limit`（封顶 200）。

数据范围沿用 apt-3，且逐查询落数据放行审计（`apartment:opslog:view`）：

- **按合同号**：SELF 仅本人经办合同；SCOPE 仅授权片区合同（合同无租约时，
  如建档即失败，SELF 只返回本人日志行，SCOPE 拒绝）；ALL 不限；
- **仅按 TraceId**：SELF/SCOPE 要求该 Trace 日志中确有本人发起的行，
  才返回该 Trace 全量行（含无账号的框架告警，保证排障完整），防枚举他人 TraceId；
- 时间窗强制最近 14 天，默认升序返回，单次 ≤ 200 条。

## 3. 新增表 / 变更

- `t_ops_log_entry`：采集日志（log_time 毫秒、level、logger_name、thread_name、
  trace_id、contract_no、username、message(2000)、stack CLOB），时间/TraceId/合同号三索引；
- `t_async_task` 增 `trace_id`（幂等 `ALTER TABLE ADD COLUMN IF NOT EXISTS` + 索引，旧库自动升级，
  旧任务缺号时工作线程以任务号兜底）；
- 权限点 25–26，仅管家/片区管家授权（MERGE 幂等）；
  schema 末尾附幂等收权 DELETE：旧库每次启动重跑脚本时 apt-3 段的
  admin「全部权限点」/supervisor「apartment 模块全部」MERGE 会把新权限授出去，
  收权语句每轮强制从 admin/supervisor 收回 25–26，保证“只放管家”在多次重启后仍成立。

全部为增量变更，旧文件库启动自动升级。

## 4. 配置

```yaml
evops:
  trace:
    enabled: true                 # 应急回退：不生成/承接 TraceId（文件格式不变）
    header-name: X-Trace-Id
    inbound-min-length: 8
    inbound-max-length: 64
  ops-log:
    enabled: true                 # 应急回退：只停 DB 采集，文件日志照常
    retain-days: 14
    queue-capacity: 2000
    flush-batch-size: 200
    flush-interval-ms: 1000
    query-limit: 200
    query-window-days: 14
    cleanup-cron: "0 23 1 * * ?"
logging:
  file:
    path: logs                    # 文件按天+100MB 滚动保留 14 天（logback-spring.xml）
```

## 5. 部署步骤

1. 备份 `data/evops.mv.db`、在用 jar 与（如有）`logs/` 目录。
2. `mvn -DskipTests package`，替换 jar 后启动；schema 自动增量升级，首次启动出现
   `运维日志采集已启动：有界队列 2000，库内保留 14 天`。
3. 用 steward01 登录确认 `/api/auth/me` 的 menus 含 `apartment:menu:ops-log`；
   主管账号确认不含。打开 `/api/apartment/ops-log/console` 粘贴令牌做一次冒烟。
4. 确认日志文件 `logs/evops-base.log` 出现固定格式行且每条带 `traceId=`。
5. 验证：按 `docs/apt-6/验证记录.md` 冒烟。

## 6. 回滚

- 纯增量：回滚 jar 后既有业务数据不受影响，新表/新列保留无副作用。
- 不回滚应急：`evops.trace.enabled=false` 停 TraceId 生成；
  `evops.ops-log.enabled=false` 停 DB 采集（检索接口查不到新日志，文件日志不受影响）。
- 日志文件滚动与格式由 `logback-spring.xml` 控制；删除该文件并重启即恢复 Spring Boot 默认日志输出，
  TraceId 响应头/响应体仍在（不影响接口契约）。
