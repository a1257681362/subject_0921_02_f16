# apt-11 租约列表拼音检索 上线说明

- 模块：`com.evops.apartment.pinyin`（新增 `PinyinIndexer`、`PinyinIndex`、
  `LeasePinyinQuery`、`PinyinIndexBackfillRunner`、`LeaseAcceptanceService`、
  `LeaseAcceptanceController`、`LeaseAcceptancePage`、`LeaseAcceptanceData`）、
  `entity/Lease`（新增两个 `@JsonIgnore` 冗余字段）、`service/LeaseService`（keyword 检索）、
  `service/LeaseExportService` + `controller/LeaseController`（导出/列表加参）、
  `task/engine/SignArchiveBusinessOps`（后台建档写入点同步生成）、`pom.xml`（pinyin4j 2.5.1）、
  `schema.sql`（增量：t_lease 两列 + 版本号 apt-11）。
- 上线日期：2026-09-25

## 1. 背景与口径

总部巡检点名、周会要求本期必须落地：租约列表检索要支持拼音。口径四句话：

1. **保存时生成**全拼与首字母两个冗余字段，**索引生成与保存同事务**；
2. 检索**同时匹配中文、全拼、首字母**；
3. **多音字取多读音集合**，不靠姓氏词库猜；
4. **大小写全半角容错**。验收时把租约样例打印出来，纸面签字确认。

## 2. 冗余字段与同事务

`t_lease` 新增两列（旧文件库启动幂等 `ALTER TABLE ADD COLUMN IF NOT EXISTS`）：

| 列 | 类型 | 内容 |
|---|---|---|
| `tenant_name_py_full` | VARCHAR(2048) | 全拼变体集合，如 `\|lefei\|le fei\|yuefei\|yue fei\|` |
| `tenant_name_py_initials` | VARCHAR(2048) | 首字母变体集合，如 `\|lf\|l f\|` |

- 每个汉字取 pinyin4j 全部无声调读音（去重），逐字读音做**笛卡尔积**；
  「乐飞」→ 乐{le,yue} × 飞{fei}，故 lefei/yuefei 都收录；「查明」「单丽」「解晨」同理
  （查 zha/cha、单 shan/dan/chan、解 xie/jie）。
- 每个读音组合写两种形式：**连写**（zhangxueyou）与**音节空格**（zhang xue you）。
- 非汉字字母/数字原样透传（外文名可检索），标点空格不占音节位；生僻字未收录读音时
  原字透传，中文原文匹配不受影响。
- 变体用 `|` 包裹分隔；组合数上限 128、字段长度上限 2000，超限按序截断并 WARN 告警
  （常见姓名远达不到）。
- **两个写入点都在同一事务生成**：
  - `LeaseService.create`（`POST /api/apartment/leases`）：`@Transactional` 内随租约 insert 一起落库；
  - `SignArchiveBusinessOps.createLeaseIfAbsent`（apt-5 签约归档后台任务步骤 6）：同一 `REQUIRES_NEW` 短事务。
  任一步失败整事务回滚，不会产生“有租约无拼音”的行。

两个字段打了 `@JsonIgnore`，不随租约接口/CSV 导出输出（与租客姓名 `@Sensitive` 脱敏口径一致，
拼音不外泄），仅供库内检索。

## 3. 三路检索

`GET /api/apartment/leases` 与 `GET /api/apartment/leases/export` 新增可选参数 `keyword`
（合同号、起租日期范围等既有条件不变，可任意组合）：

- keyword 含汉字：按 `tenant_name` 子串匹配（中文原文一路）；
- keyword 为纯字母/数字：OR 匹配三路——
  1. `tenant_name LIKE`（兜住外文名/姓名中字母片段）；
  2. `tenant_name_py_full LIKE '%|前缀%'`（全拼变体**起点**前缀）；
  3. `tenant_name_py_initials LIKE '%|前缀%'`（首字母变体起点前缀）。
- 连写输入（zhangxue）匹配连写变体；带空格输入（zhang xue）额外匹配音节空格变体。
- **变体起点**设计避免音节中间误命中：检索 `uef`（yuefei 的中间片段）不命中「乐飞」。
- LIKE 模式经 MyBatis-Plus `{0}` 占位符参数化绑定，无 SQL 注入面。
- 数据范围（SELF/SCOPE/ALL）、数据放行审计口径与既有列表检索完全一致；
  审计 `query_params` 追加 `keyword=原始输入`。

**大小写/全半角**：检索词逐字 NFKC（全角 ｌｅ→半角 le、全角空格→半角）后小写，
与索引端同一份归一化代码（`PinyinIndexer.normalKeyword` 与索引生成共用 NFKC 口径），
`LEFEI`、`ｌｅｆｅｉ`、`ＬＦ`、`ｌｅ　ｆｅｉ` 均命中。

## 4. 历史数据回填

`PinyinIndexBackfillRunner`（`ApplicationRunner`，Order=20）：旧文件库升级后两列为 NULL，
启动时挑「两列任一为 NULL」的租约，每批 500 条一个独立事务按建档同口径回填；
批失败整批回滚、已提交批不返工，下轮启动续跑。新建档行已同事务写入，不会进入回填集合。

## 5. 验收打印页（纸面签字）

- `GET /api/apartment/leases/acceptance/console`：自包含 HTML 空壳（不鉴权，浏览器可直达，
  令牌页内粘贴，仅存本机 localStorage；真正鉴权在数据接口，与 apt-6 运维日志台同一模式）。
- `POST /api/apartment/leases/acceptance/samples`（权限 `apartment:lease:create`）：
  幂等播种 5 条样例租约——乐飞/查明/单丽/解晨/张学友，合同号 `HT-PY-0001~0005`；
  按合同号查重，已存在跳过。
- `GET /api/apartment/leases/acceptance/data`（权限 `apartment:lease:view`）：
  返回样例租约（含拼音冗余字段供核对）+ 16 条服务端验收用例执行结果
  （中文、全拼连写/空格、首字母、多音字各读音、大小写、全角、前缀区分、负例），
  用例查询条件直接复用线上 `LeasePinyinQuery`，**验收口径=线上口径**。
- 页面仅在全部用例通过时给出“同意验收”结论；点「打印」走浏览器打印，
  `@media print` 隐藏操作区，只留样例表、用例结果与**验收人/复核人/日期签字栏**，纸面签字归档。

## 6. 权限与兼容性

- **不新增权限点**：复用 `apartment:lease:view`（检索/验收数据）、
  `apartment:lease:create`（播种）、`apartment:lease:export`（导出），
  管家/片区管家/主管/管理员既有授权不变。
- 既有检索（不带 keyword）行为不变；合同号精确、起租日期范围、数据范围、脱敏均无改动。
- pinyin4j 2.5.1 为纯 Java 库，无传递依赖，JDK 8 兼容。

## 7. 回滚步骤

1. 代码回滚到 apt-10 版本并重启：keyword 参数被忽略，列表/导出恢复 apt-10 口径；
   两列保留在库中不影响任何既有读写（实体字段随代码移除后 MyBatis 不再访问）。
2. 如需彻底清列（一般不必）：停服后
   `ALTER TABLE t_lease DROP COLUMN tenant_name_py_full;
    ALTER TABLE t_lease DROP COLUMN tenant_name_py_initials;`，
   删除 `t_evops_schema_version` 中 `version_no='apt-11'` 行。
3. 验收样例租约（`HT-PY-0001~0005`，房源编号 `PY-SAMPLE-001`）为独立数据，
   不影响真实业务；如需清理按合同号删除即可。
