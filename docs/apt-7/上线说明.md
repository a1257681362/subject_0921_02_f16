# apt-7 出租率额度预占模型 上线说明

- 模块：`com.evops.apartment.quota`（新增：实体/mapper/dto/service/调度/web）、
  `schema.sql`（增量：3 张表 + 权限点 27–32 + 示例小区 300 额度种子）、`application.yml`（`evops.quota.*`）
- 上线日期：2026-09-23

## 1. 背景与模型

公寓楼年检每年卡在出租率这项：出租率有额度控制，以前申请建档直接扣额度，并发下容易超扣。
本期改为**预占模型**，按小区维度控额：

```
申请(RESERVE)                 确认(CONFIRM)
余量 ──reserved+1──▶ 预占中 ─────────────────▶ 已实扣 occupied+1 / reserved-1
                      │  20 分钟内有效
                      ├─ 主动取消(RELEASE_CANCEL)  ┐
                      └─ 20分钟超时(RELEASE_TIMEOUT)┴─▶ reserved-1 余量回补
```

- **申请先占余量**：`available = total - occupied - reserved`，申请即 `reserved +1`；
- **确认才实扣**：确认把预占额转为已实扣（`occupied +1, reserved -1`）；
- **取消或超时自动释放**：管家可主动取消；申请后 20 分钟未确认，后台扫描自动释放；
- **余量全程可查**：每次变化落一条流水（含变化后三余额），可按流水从 0 回放对账；
- **配额调整留痕**：配额开户/上调/下调均落 ADJUST 流水，下调不得击穿在途单；
- **同单不可重复预占**：同一合同号同时只允许一笔活跃预占单，库内唯一索引兜底并发。

### 不超扣的两道保险

1. 申请的“余量检查 + reserved+1”是**一条带 `WHERE total - occupied - reserved >= 1`
   的条件更新**（`QuotaBalanceMapper.reserve`），并发申请由数据库行锁串行化，
   余量不足者更新 0 行、业务失败——不依赖先查后写，绝不超扣；
2. 同单并发申请由预占单生成列唯一索引 `uk_quota_hold_active_biz` 兜底，只成功一笔。

## 2. 新增接口（`/api/apartment/quota/**`，均需登录）

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| POST | `/holds` | `apartment:quota:apply` | 申请预占（占 1 个余量，返回单号与到期时间） |
| POST | `/holds/{holdNo}/confirm` | `apartment:quota:confirm` | 确认实扣（过期/已释放/已确认拒绝） |
| POST | `/holds/{holdNo}/cancel` | `apartment:quota:cancel` | 主动取消释放（与超时释放互斥，只生效一次） |
| GET | `/holds` | `apartment:quota:view` | 预占单检索（community/status/bizRef 可选） |
| GET | `/balances?community=` | `apartment:quota:view` | 余量（total/occupied/reserved/**available**） |
| GET | `/journals?community=` | `apartment:quota:view` | 额度流水（可按 changeType/bizRef 过滤） |
| POST | `/adjustments` | `apartment:quota:adjust` | 配额开户/调整（仅主管、管理员） |

数据范围沿用 apt-3，每个写/查动作落数据放行审计：

- SELF：可在任意小区**申请**（与租约建档口径一致），但只能确认/取消**本人申请**的预占单，
  `GET /holds` 只见本人单；
- SCOPE：只能在授权小区操作与查询（`requireCommunityInScope`），列表只见授权小区；
- ALL：不限。
- `GET /journals` 必须指定小区；流水对有查看权的经办角色可见（含主管的 ADJUST 记录，留痕透明）。

五类流水（`change_type`）：`RESERVE` / `CONFIRM` / `RELEASE_CANCEL` /
`RELEASE_TIMEOUT` / `ADJUST`。

## 3. 新增表

- `t_quota_balance`：小区额度账（uk community），`total_amount/occupied_amount/reserved_amount`；
- `t_quota_hold`：预占单（uk hold_no；状态 HELD/CONFIRMED/RELEASED，只增不删）。
  **同单唯一**靠 H2 生成列：
  `active_biz_ref GENERATED ALWAYS AS (CASE WHEN status IN ('HELD','CONFIRMED') THEN biz_ref ELSE NULL END)`
  + 唯一索引（唯一索引允许多个 NULL）——释放后同合同可重新申请，同时只可能有一笔活跃单；
- `t_quota_journal`：额度流水（只增不改，记录 delta_total/delta_occupied/delta_reserved
  与变化后三余额、hold_no、biz_ref、request_no、operator、biz_time）。
- 权限点 27–32：管家/片区管家授 27–31（菜单+申请/确认/取消/查看），
  主管授 27–32（含配额调整），管理员显式授 27–32。
- 种子：`示例小区` 开户额度 **300**（与片区管家 SCOPE 授权小区一致），仅在无账时播种，
  后续以调整接口为准，重启不覆盖。

全部为 `CREATE TABLE IF NOT EXISTS` / `MERGE` 幂等增量，旧文件库启动自动升级，无手工 DDL。

## 4. 配置

```yaml
evops:
  quota:
    enabled: true                 # 应急开关：停超时扫描（已预占额度需人工取消释放）
    hold-ttl-minutes: 20          # 预占有效期，超时未确认自动释放
    sweep-interval-ms: 30000      # 到期扫描间隔（最坏多占 30s，不超扣）
    sweep-initial-delay-ms: 10000
```

扫描为 fixed-delay 单线程逐单独立事务释放；多实例/与主动取消并发均安全：
释放是 `WHERE status='HELD'` 的条件更新，同一单只有一方成功并回补账上预占额，
输的一方不动账、不写流水。

## 5. 部署步骤

1. 备份 `data/evops.mv.db` 与在用 jar。
2. `mvn -DskipTests package`，替换 jar 后启动；schema 自动增量升级，
   种子小区 `示例小区` 额度为 300（其他小区需主管调 `/adjustments` 开户）。
3. steward01 登录确认 `/api/auth/me` 的 menus 含 `apartment:menu:quota`、
   buttons 含 apply/confirm/cancel/view、**不含** adjust；supervisor01 含 adjust。
4. 冒烟：申请 → 查余量（reserved+1、available-1）→ 确认（occupied+1）；
   再申请一单 → 取消（余量回补）；`/journals` 可见 RESERVE/CONFIRM/RELEASE_CANCEL 流水。
5. 超时：申请后等 20 分钟（或测试环境调小 `hold-ttl-minutes`）观察自动释放与 RELEASE_TIMEOUT 流水。
6. 逐条结论见 `docs/apt-7/验证记录.md`。

## 6. 回滚

- 纯增量：回滚 jar 后三张新表保留，无其他模块读写，不影响 apt-1～apt-6 既有功能。
- 不回滚应急：`evops.quota.enabled=false` 停超时自动扫描（已预占额度需主管/管家手工取消释放）；
  接口与额度账不受影响。
- 额度数据修正：配额只能走 `/adjustments`（留痕），严禁直接改库；
  如下调受阻于在途单，先取消/确认相关预占单使占用回落，再下调。
